# Database Overview

## Overview

This document provides an overview of the database architecture for SupportOS. The platform uses PostgreSQL as its primary relational database and Prisma ORM for database access and schema management.

The database is designed to support a multi-tenant SaaS architecture with strong data consistency, scalability, and security.

---

# Database Goals

The database architecture is designed to achieve the following goals:

- Multi-tenancy
- Data Integrity
- ACID Transactions
- High Performance
- Scalability
- Security
- Auditability
- Extensibility

# Multi-Tenant Design

SupportOS follows a **Shared Database, Shared Schema** multi-tenant model.

Each record belongs to exactly one organization.

Example:

Organization

↓

Users

↓

Tickets

↓

Messages

↓

Knowledge Base

↓

Analytics

Every query must include an Organization ID filter to ensure tenant isolation.

# Naming Conventions

Tables:

- Singular PascalCase in Prisma models
- snake_case in PostgreSQL (generated by Prisma)

Examples:

- Organization
- User
- Ticket
- Message
- KnowledgeDocument

Fields:

- camelCase

Examples:

- createdAt
- updatedAt
- organizationId
- ticketId

---

# Primary Keys

Every table uses:

- UUID

Example:

id UUID PRIMARY KEY

Benefits:

- Globally unique
- Suitable for distributed systems
- Harder to enumerate than integers

---

# Foreign Keys

Relationships are enforced using foreign keys.

Example:

Ticket

↓

organizationId

↓

Organization.id

This guarantees referential integrity.

---

# Soft Deletes

Important entities use soft deletion.

Instead of deleting records:

deletedAt TIMESTAMP NULL

Benefits:

- Auditability
- Data recovery
- Historical reporting

---

# Audit Fields

Most tables include:

- createdAt
- updatedAt
- deletedAt (optional)
- createdBy (optional)
- updatedBy (optional)

These fields improve traceability.

---

# Transactions

Database transactions are used for operations involving multiple related changes.

Examples:

- Organization creation
- User invitation
- Ticket creation with initial message
- Ticket assignment
- Knowledge document upload

This ensures data consistency.

---

# Performance Strategy

Performance is improved through:

- Proper indexing
- Query optimization
- Redis caching
- Pagination
- Lazy loading where appropriate

---

# Security

The database enforces:

- Tenant isolation
- Foreign key constraints
- Parameterized queries
- Password hashing (application layer)
- Encrypted connections (TLS)

---

# Backup Strategy

Recommended:

- Daily backups
- Weekly snapshots
- Point-in-time recovery
- Regular restore testing

---

# Future Considerations

Future enhancements include:

- Read replicas
- Database sharding

- Event sourcing

---

# Summary

The SupportOS database is designed as a secure, scalable, multi-tenant relational database. PostgreSQL and Prisma provide a strong foundation for transactional consistency, while pgvector enables AI-powered semantic search. The schema is structured around logical business domains, ensuring maintainability and future scalability.
